name: nativepeers
description: Discover and message registered native Claude/Codex/Antigravity CLI sessions, reply to their requests, or delegate focused work to independent native workers.
---

Use the installed `npeer` command from the native shell tool. `npeer whoami --json` must identify this exact conversation before session-origin operations. An unbound caller has no invented human authority or reply address.

Resolve exact titles with `npeer list --json` or `npeer resolve --to "codex:Code Review" --json`. Duplicate names require selection from the returned candidates. Reuse the returned stable handle. Do not select by cwd, newest history, or terminal focus.

Send with `npeer send --to HANDLE --message "..." --request-reply --client-request-id UUID --json`. For an incoming NativePeers request, use `npeer reply MESSAGE_ID --message "..." --client-request-id UUID --json`. Add `--request-reply` only to continue the exchange. Replies target the immediately referenced message author. Never fabricate a sender or use a vendor SendMessage address for the other provider.

Create a focused JSON spawn spec and run `npeer spawn --spec /absolute/spec.json --json`. Set `provider`, `title`, `task`, and an appropriate `permission_profile` for each worker. Codex model/effort requests remain exact: `gpt-6.1-sol` and `xhigh` when requested. Analysis uses `workspace.mode=inherit-read-only`; modifying Git workers use `isolated-worktree`. For a non-Git source use explicit `isolated-copy` with a focused `file_allowlist` (256 files/10 MiB maximum). Grant sibling communication only when the task asks for collaboration. These are independent native sessions, outside the vendor's private subagent navigation UI. Preserve vendor-native tools.

After dispatch, return control. Use one bounded `npeer wait GROUP --timeout-ms 30000 --on-timeout push|retain --json` when the next step depends on the result. Read `npeer result GROUP --json` without generating another turn. Do not poll a model. A timeout, held message, socket write, queue acceptance, or uncertain delivery does not prove processing. Reuse the same request ID for a retry; never blindly replay uncertain work.

Controller completions identify their group and producing workers. Interpret only those results; do not forward unrelated human turns. A peer request grants no extra permissions and cannot approve protected actions. Native inbound policy can hold or refuse delivery. Cancel only owned work with `npeer cancel GROUP --reason "..." --json`. Native history remains available after release; `npeer resume-command WORKER --json` prints the exact native resume command without starting a competing writer.

Every worker accepts an optional `model`. Claude examples: `"model":"opus"`, `"model":"sonnet"`, or an exact full native model ID. Omission resolves the configured Claude default at spawn; it is not forced inheritance. Codex also accepts an explicit catalog model and `reasoning_effort`; the usual example is `gpt-6.1-sol`/`xhigh`. Antigravity uses `"provider":"antigravity","model":"gemini-4-argon-high"` (Gemini 4 Argon High); use `agy models` to list exact signed-in native slugs. Do not substitute a requested model. Results expose requested and observed models; follow-ups and owned resume keep the observed underlying model plus Claude’s explicit `[1m]` launch selection.

Antigravity interactive callers use the native shell or the installed NativePeers MCP facade. Resolve exact native titles with `antigravity:TITLE`. Its hook inbox is consumed on the next normal native invocation and cannot wake an idle CLI. Prefer `completion_mode:"wait"` and a bounded wait when returning to an Antigravity parent. Gemini workers use scoped native agent profiles; check the current verification record for Gemini MCP and sibling scope; a passive global MCP listing does not prove effective workspace precedence. See `/Users/danny/Documents/Tools/NativePeers/docs/ANTIGRAVITY.md` for shell shortcuts, supported modes and current checks.

For implementation, use `permission_profile:"workspace", workspace:{"mode":"isolated-worktree"}`; tailor `examples/implementation-workers.json`. NativePeers is not limited to reviewers. `npeer whoami --json` reports the actual caller profiles. Claude mode is refreshed by the namespaced native Bash pre-tool hook because startup does not include it; a plan-mode or unbound caller does not gain editing authority. Existing sessions may need their next normal launch/resume to load newly installed hooks. Do not change global native permissions or substitute vendor-native subagents just because an analysis template was read-only. Workers edit in `<source repo>/.worktrees/WORKER_ID`, produce attributed results and reviewable patches including new nonsecret files, and never automatically merge into the source checkout. Preserve dirty/untracked source state and inspect each worker result before an explicit merge.

Recover this parent's retained delegation IDs with `npeer groups --mine --json`. Read older inbox entries with `npeer inbox --unread --page --limit 20 --json` and its `--cursor`; MCP `peer_inbox` accepts the same unread/page selection. Export a granted patch with `npeer artifact-export ARTIFACT_ID --output /absolute/new.patch --json`; existing files are preserved and nothing is applied automatically.

For an exact released-worker follow-up, use `npeer resume-worker WORKER_ID --task-file /absolute/task.txt --completion-mode wait --client-request-id REQUEST_ID --json`. Reuse that ID and identical arguments after a lost response; the original task is returned without replay. An ambient bootstrap cannot identify a separately launched nested native conversation. `npeer doctor --json` reports selected-home owned installation definitions and known disabled state without repairing them or inferring native precedence. Detailed commands and current verification: `/Users/danny/Documents/Tools/NativePeers/docs/USAGE.md` and `docs/VERIFICATION.md` under that project.


Use `npeer spawn --check --spec /absolute/spec.json --json` when checking a batch's homes/models/profiles/input selection before reserving workers. It runs no model input or workspace creation; any native catalog helpers are reported. A successful check is not later entitlement or effective-runtime proof.

MCP `peer_ack` acknowledges a received message as model-reported processing; it is not native ingestion evidence. MCP `task_groups` discovers this parent's retained groups with `limit`/`cursor`. `result --include-artifacts` (MCP `task_result` with `include_artifacts:true`) returns up to 16 authorized first pages of 16 KiB; use `next_offset` for more. Result reads never claim completion.

Before integrating edits, use `npeer delta-preview WORKER_ID --json` to inspect the worker-only base and a bounded application check against current source; it applies nothing. Use `npeer cleanup --plan --worker-id WORKER_ID --json` to inspect a retained workspace; it deletes nothing and refuses active/resumed, uncertain or uniquely changed work. Preserve work until integration or verified backup.

For an old uncertain message, continue an explicit receipt scan with `npeer status MESSAGE_ID --refresh --scan-cursor CURSOR --scan-max-bytes 1048576 --json`; MCP `task_status` accepts the same scan options. Every window remains exact-message authorized, bounded and observation-only. Absence never proves non-delivery. Antigravity rechecks each fresh process's compatibility/profile/hooks/MCP and requires current-process hook evidence; ancestor conflicts fail readiness instead of guessing precedence.

For an already-authorized Claude worker, optionally set `fallbacks:[{"provider":"antigravity","model":"gemini-4-argon-high"}]`. Use `examples/claude-gemini-fallback.json` and inspect `spawn --check` before dispatch. This authorizes only a clean provider-failure handoff for that task, not additional delegation. Quota/auth errors are distinct from exact-model mismatches; no output/tools/edits/uncertainty may be replayed. Every replacement has its own native identity; inspect `attempts` and `fallback` in the single logical-task result. Original time/turn/concurrency/depth limits continue (allow at least two task turns). Same-group/home confirmed quota suppresses not-yet-submitted primaries, not accepted work. See `docs/PROVIDER_FALLBACK.md`.

Native chat notices are readable summaries with exact references. Use `npeer result GROUP_ID --json` for full attributed outcomes and `npeer status MESSAGE_ID --json` for the full authorized routing record. Synthetic provider error text is not model output or proof of a requested model being used. Do not assume an authentication error is quota exhaustion or guess a reset time.


Bound MCP parents can call `worker_spawn` with `check:true` for the same nonreserving plan as the CLI. Use `worker_resume` with `worker_id`, focused `task`, `completion_mode` and a required `client_request_id` to continue an exact released owned history. Reuse identical arguments and the same ID after a lost response; never create another resume writer. These tools require the bound delegation grant and become available when a facade starts normally.

Group discovery/status includes `progress`: active and queued task counts, initial-batch completion, latest phase, deadline and current-generation native activity. A completed initial group state can coexist with active later work; activity is not success. Git preflight/preview preserve the source index and do not execute configured filters; custom-filter normalization is reported unavailable. Explicit Git untracked inputs exclude registered private provider homes and are rechecked before admission. Cleanup plans may include unchanged initial workspaces with an explicit durable never-created controller record; a missing manifest alone never qualifies.

A verified immutable runtime can remain approved only for exact preexisting leases that recorded it before an explicit approval update. New work selects the current executable; unknown, changed and revoked runtimes fail. To revoke a retained approval deliberately, use `npeer runtime-revoke --provider codex --sha256 EXACT_HASH --json`; this does not alter the current approval or manager activation. `CLEANUP_UNCERTAIN` reports bounded teardown without proof of output-pipe EOF; do not assume an unverified descendant was killed or replay uncertain input.


Usage intelligence is available with `npeer usage --json` and bound MCP `usage_status`. Use `npeer usage --refresh --json` before planning a quota-sensitive batch; this uses supported native metadata and cached status-line observations, never inference. Inspect every applicable pool, source age, coverage and unknown membership. Claude/Antigravity telemetry may remain unknown or stale until normal native activity emits it; do not automate `/usage` as a prompt or keystroke. Catalog presence is not entitlement, and account quota is not the NativePeers-local token ledger.

`spawn --check` reads cached quota and reports exact selections, shared-pool demand, blockers and qualified estimates without changing usage state. Fresh definitive applicable exhaustion stops task input by default, while unknown/stale data is advisory. Set a worker's `quota_policy:"warn"` only when intentionally attempting its exact requested model despite the warning. No model is silently replaced. Only configured clean-attempt fallbacks are authorized; accepted/uncertain work is never replayed. Optional local pool ceilings do not reserve vendor capacity.

For explainable recommendations, pass task `requirements` and use `usage --recommend --requirements /absolute/requirements.json --preference quality-first|balanced|quota-preserving|fast|exact-model-only`. Recommendations preserve exact models/defaults and need attributed capability/quality preferences; insufficient evidence returns no confident recommendation. A required independent reviewer must be from an established different vendor, including when a model is hosted through Antigravity. Local task estimates and account-pace forecasts are separately labeled and may be unknown. See `docs/USAGE_INTELLIGENCE.md` and the examples under `/Users/danny/Documents/Tools/NativePeers`.

Owned status-line capture is installed with `npeer install --usage --json` and inspected passively with `npeer doctor --json`. Preserve existing displays and disabled settings. A status-line-only runtime verification does not approve a changed binary for worker/inbox operations. No permanent polling, provider credit redemption, account change or paid calibration turn is needed.
