### 🔴 Critical Issues (Must Fix)

**Introduced in this implementation:**

1. **RV-01: Concurrent hook edits can be overwritten** - `nativepeers/install.py:141` _(unique to CA1's lane)_
   - Problem: The expected configuration hash is read after the merge input, so it can identify newer bytes than the replacement content.
   - Risk: Install reads A, an editor saves unrelated changes B after merged() returns, then compare_write hashes B and replaces it with a merge derived from A. Uninstall has the same ordering; the unrelated edit is lost.
   - Fix: Capture and retain the expected hash before reading/merging each target on install and uninstall.

```python
expected = file_hash(path)
before, after = self.merged(path, provider, remove=remove)
if before != after:
    compare_write(path, encoded(after), expected)
```

2. **RV-04: A task wait consumes its whole batch notification** - `nativepeers/supervisor.py:230` _(unique to DB1's lane)_
   - Problem: A wait for an initial task claims the shared phase route, but returns only that task's result.
   - Risk: Spawn A+B with push, wait for A, finish A first: the shared route becomes NOTIFICATION_UNKNOWN. B then finishes and notify() suppresses the aggregate, so B's completion is never pushed to the parent.
   - Fix: Only a group wait or a wait covering every task of its phase can claim that notification.

```python
phase_tasks = self.phases()[str(generation)]
owns_notification = handle == self.id or phase_tasks == [handle]
if owns_notification:
    claim_waiter_route()
# A partial task read leaves the batch notification unchanged.
```

3. **RV-05: Task cancellation interrupts unrelated work on the same worker** - `nativepeers/supervisor.py:163` _(unique to DB1's lane)_
   - Problem: Every task handle expands into a worker-wide cancel, sets stopping, cancels all queued tasks and releases the worker.
   - Risk: W runs A while B is queued; cancel(B) sends W a blanket cancel and interrupts A. B and other queued tasks are also canceled, despite the requested handle identifying only B.
   - Fix: Cancel queued tasks atomically; claim queued input before provider submission; target running cancellation by exact task and preserve other accepted task records.

```python
with journal.transaction() as db:
    task = lookup_exact_task(db, handle)
    if task['state'] == 'QUEUED':
        cancel_only_this_task(db, task)
    elif task['state'] not in TERMINAL:
        send_task_specific_interrupt(task)
# Worker claims only QUEUED tasks of its exact worker/generation:
claimed = db.execute("UPDATE tasks SET state='RUNNING' WHERE task_id=? AND worker_id=? AND generation=? AND state='QUEUED'", ids).rowcount
if not claimed:
    return
```

### 🟡 Warnings (Should Fix)

**Introduced in this implementation:**

1. **RV-02: Reinstall overwrites edited installed skills** - `nativepeers/install.py:135` _(unique to CA1's lane)_
   - Problem: Path membership in owned_files authorizes replacement even when the current skill differs from its recorded installed hash.
   - Suggestion: Permit absent/desired/unchanged-owned content only, carry the validated hash to replacement, and preserve local edits with OWNERSHIP_CONFLICT.

2. **RV-03: Writing workers can start from different baselines** - `nativepeers/delegation.py:149` _(unique to CA1's lane)_
   - Problem: Each sequential prepare() takes a new snapshot; the preliminary baselines are unused. A tracked edit between worker preparations makes one batch start from V1 and V2.
   - Suggestion: Capture one batch baseline and require each preparation to match it before starting any provider task.

3. **RV-06: Completion bodies use character limits instead of byte limits** - `nativepeers/supervisor.py:266` _(unique to DB1's lane)_
   - Problem: Four valid 2,000-character CJK summaries exceed the 12-KiB UTF-8 body limit. JSON escaping can expand text further, causing a retained result instead of its requested push.
   - Suggestion: Fit the final serialized body within the byte budget, preserving attribution/artifact handles and indicating truncated summaries.

4. **RV-07: Wait fails for retained terminal work after supervisor exit** - `nativepeers/delegation.py:210` _(unique to DB1's lane)_
   - Problem: wait always calls the removed finite supervisor socket, returning SUPERVISOR_LOST for already completed retained tasks/groups.
   - Suggestion: Read terminal results locally without changing notification ownership; contact the supervisor only for active work.

5. **RV-08: A single-request live batch cannot settle** - `nativepeers/budget.py:48` _(unique — outside both primary lanes)_
   - Problem: admit records admitted_at at t1, opens batch at t2>t1; settle removes sole outstanding request, then filters settled records admitted_at>=t2, gets empty max(), raises ValueError; change does not persist settled state, leaving reservation admitted and active interval open.
   - Suggestion: Use one admission timestamp for both fields and a stable batch-membership contract; cover one request, reverse-order overlapping settlement and legacy ledger first-admission timestamps without altering production ledger.

6. **RV-09: Queue timeout and caller cancellation do not bound helper lifetime** - `nativepeers/adapters/native_delivery.py:27` _(unique — outside both primary lanes)_
   - Problem: native queue helper hangs/ignores TERM; communicate times out after25s, then unbounded process.wait blocks caller/admission lock forever; cancellation exits without subprocess cleanup.
   - Suggestion: Bound TERM grace, KILL and reap only the exact created queue helper on timeout/cancellation; keep DELIVERY_UNKNOWN and never replay; test fake helper without native inputs.

7. **RV-10: Definite transport failures are successful CLI responses** - `nativepeers/cli.py:117` _(unique — outside both primary lanes)_
   - Problem: bound sender -> native inbox TARGET_GONE/REJECTED -> Router records and returns failed attempt outcome -> main sets ok true and leaves exit0 because only uncertainty/wait expiry mapped.
   - Suggestion: Map definite failed send/reply outcomes into stable error envelope and documented nonzero exit codes while retaining message/request IDs and outcome; tests zero-code only actual accepted states.

### ✅ Good Practices

- Idempotency lookup precedes mutable title resolution and uncertain delivery is never blindly replayed.
- Replies verify the recorded recipient, target the immediate author and retain exchange correlation.
- Caller binding validates exact native ownership/incarnation instead of choosing a recent transcript.
- Native workers use separate identities, a concurrent readiness barrier and scoped effective tools.
- Artifact grants are included in send/delegation journal transactions.
- Worktrees preserve the original checkout; retained results and native histories survive notifications and cleanup.
