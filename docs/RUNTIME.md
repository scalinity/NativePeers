# Runtime and permissions

The own SQLite WAL journal stores identities, incarnations, immutable requests, uncertain native attempts, attributed tasks/results, completion claims and leases. Native provider databases/transcripts are never edited. Short lifecycle hooks verify native ancestry and register the exact UUID/owner/PID-start identity. A transient shell, matching cwd or a thread ID alone is insufficient to impersonate a session. Fixed MCP facades are bound to one owned worker lease; no tool accepts an arbitrary sender field.

Claude interactive delivery uses its installed native inbox protocol and preserves its inbound policy. Codex interactive delivery uses the native queue without adding `--no-daemon` to the sender. The original loaded owner consumes the queue. Sender validation, ordinary recipient configuration, standalone topology and unloaded-target behavior are separate facts. The required owner/return probes selected the native queue; no conditional Rust patch was installed. Unowned Codex processes must have verified terminal stdin to qualify as standalone TUI owners; a private app-server pipe is not advertised as TUI queue ingress. Codex defers SessionStart hooks until its first native turn, so an untouched empty session retains its native name but is not yet a registered NativePeers peer. Existing live peers are never resumed by a second writer for message injection.

Each group supervisor detaches without terminal streams, owns lease pipes to worker controllers and exits after work/grace or loss of the owning parent. Codex workers use private stdio app-server processes from immutable managed package paths. Claude workers use the installed native CLI with structured headless turns and the normal native authentication route. The controller persists across serialized Claude turn processes. Inherited native hooks report owned-worker observations without replacing the controller route or unregistering between turns.

Claude's initial MCP snapshot is populated with permitted tool names while calls remain nonmutating in `RESERVED_UNBOUND`. After the emitted native ID is verified, the same facade becomes bound. Codex additionally verifies the refreshed effective MCP inventory before input. NativePeers tools on a Codex worker have an explicit worker-local `default_tools_approval_mode="approve"`; the fixed facade enforces the lease and granted targets. Other MCP/plugin tools are disabled only in the new worker's runtime overlay. Parent registrations and permissions are preserved. Claude analysis exposes Read/Glob/Grep and the scoped facade; Codex analysis uses the native read-only sandbox. Startup project/user hooks remain trusted local execution context; this is not isolation from malicious same-UID startup code.

The native CLI owns authentication: Codex uses the existing ChatGPT sign-in; Claude uses the existing claude.ai Max route. No OAuth credentials are extracted, borrowed, translated into an API key or placed in backups. Launch environments preserve intended provider-home/auth variables while excluding parent messaging credentials, bindings and `CLAUDE_ENV_FILE`. Existing parent YOLO behavior and `features.daemon_auto_start=false` are unchanged.

Installed integration and native permission to run unattended are different. The installer adds owned hooks and skills; it does not globally accept cross-session requests or rewrite native permission policy. Live fixtures disclose their explicit `dontAsk`/existing Codex full-access settings and test scope. An ordinary auto-policy session may hold, refuse or ask about a request. A model can also refuse a task outside the human's delegated scope even after native ingestion; that is not a transport success or a reason to impersonate the user.

A bounded wait leases completion delivery only for that call. Timeout/disconnect releases the claim and chooses push or retain. An uncertain tool-result write or native push is retained as uncertain instead of automatically duplicated. Immutable result reads remain available. Push completion uses a separate controller actor for that group/generation. Exactly one reasoning model is used per native worker; supervisors and aggregation are ordinary local code.

Compatibility receipts bind the verified native executable hashes. A changed binary blocks affected worker launch/native delivery until its changed seam is revalidated; existing immutable owned workers retain their package path. NativePeers does not activate an unrelated Codex update, disable the hourly manager job, drop patches or roll back completed naming/MCP work. Revalidate installed schemas, native hook/queue/MCP behavior and the relevant live checks for a new runtime; use the manager's supported lock/activation mechanism for any separately authorized package change.


Antigravity CLI uses its native UUID and exact CLI-owner hooks, structured headless worker turns, native Google authentication and NativePeers' existing finite controllers. Its inbound hook offers attributed pending text at the next normal native invocation; it does not wake idle conversations. Owned Gemini role titles are NativePeers labels, distinct from native history titles. Analysis tools and the fixed PreToolUse gate restrict the new worker only. See [Antigravity](ANTIGRAVITY.md) for current verification, MCP/sibling limitations and the native startup-naming boundary. IDE/App backend takeover remains outside support.

Claude SessionStart does not expose permission mode; its short Bash PreToolUse hook refreshes that exact interactive peer without changing identity/incarnation. Plan mode retains analysis-only grants. Unowned Codex historyless background hooks do not register as interactive peers or replace a TUI parent; registration verifies the hook UUID against its native history header. New Codex workers disable native background memory work only in their own runtime overlay. Supervisor lease loss now has one uncancelled worker cleanup path. These changes preserve native user settings and vendor tools.

## Worker history visibility

New Codex workers require the managed runtime's worker-only history capability before creation. The private app-server selects durable `{"custom":"nativepeers-worker"}` source metadata before indexing; ordinary launches retain their source. The initialize acknowledgment and returned native source are checked separately, and Desktop verification remains a separate result. Legacy retained leases keep their executable and UUID, with unsupported visibility reported explicitly. History-preserving cleanup and exact archived resume are described in [worker history visibility](WORKER_VISIBILITY.md).

## Explicit provider failure handoff

Claude synthetic API errors are classified before inference-model binding. A terminal quota/auth error with zero reported usage and no observed model/tool work can hand off only to explicitly selected Gemini candidates, with unchanged editing input and stopped original writers. One logical task retains separately attributed immutable attempts, a shared original deadline/turn allowance and its original completion phase. A group-local provider/home quota record prevents later pointless submissions; it is neither global health monitoring nor permission to replay accepted input. See [PROVIDER_FALLBACK.md](PROVIDER_FALLBACK.md). Native input presentation is separate from the immutable routing envelope; receipt observers support both the exact readable frame and legacy envelopes.

Owned leases record their verified executable fingerprints. Explicit compatibility renewal scopes retained old approvals to the exact already-verified lease IDs, preserving immutable path/hash and verification scope. New launches use the current approval. Retained approval can be revoked through local maintenance; it is neither entitlement nor indefinite native compatibility. Codex output-reader teardown is bounded separately from process exit. An inherited output pipe reports CLEANUP_UNCERTAIN without signaling a dead leader's group or claiming an unverified descendant exited.

Usage intelligence and its exact commands, native sources, installation, freshness, quota overrides, recommendation constraints and forecast limitations are documented in [USAGE_INTELLIGENCE.md](USAGE_INTELLIGENCE.md). `install --usage` composes only owned status-line capture; it preserves existing display commands and does not update worker/inbox runtime approval.


Owned release requires a matching-generation positive native-process and stdout/stderr EOF record. Captured PID/start/UID births remain owned across exec and session/group changes; unknown inspection is not death. Caller authentication separately retains executable and group checks. Codex parser completion cannot stand in for output EOF. Failed group cleanup stays visible and reserved. See [review 2551947](REVIEW_2551947.md) for tested schedules and current runtime boundaries.

Controller control writes have a one-second drain deadline. Release closes the exact lease even when control delivery stalls or the release coroutine is canceled. A frame already written remains an uncertain handoff. A successfully created controller is tracked before initial identity inspection; unknown inspection keeps ownership counted until closure is established. Native model-catalog reads independently bound process exit, captured descendants and stdout/stderr EOF.

Interactive recipients receive message bodies and context references through inbox or status only after native ingestion is established. The recorded sender retains access to its own message. Integration initialization checks the runtime approval under the same lock as its write and preserves an approval recorded concurrently.
